# Hallucination

主流程第 2 个节点（`type: game`，`game: hallucination`）。
代码：`arcade_ftw_fe/src/games/hallucination/`。

## 玩法

一次显示一条 **AI 的回复**，观众判断这句可不可信，从五档里选一个：

| 档位 | 分值 |
|---|---|
| Very Doubt | −10 |
| Doubt | −5 |
| Not Sure | 0 |
| Partial Trust | +10 |
| Full Trust | +20 |

题目内容是「用户问了什么」＋「AI 答了什么」，玩家只对**回复**做判断。

## 计分：对称，符号由对错决定

每题有一个**真值**：这句 `trust`（站得住）还是 `doubt`（幻觉）。

```ts
score = 档位分值 × (真值 === trust ? 1 : -1)
```

上表的分值是**真值为 trust 时**的得分；真值是 `doubt` 时整体取反。所以：

| 情况 | 得分 |
|---|---|
| 句子是真的 + 选 Full Trust | **+20** |
| 句子是幻觉 + 选 Full Trust | **−20** |
| 句子是幻觉 + 选 Very Doubt | **+10** |
| 句子是真的 + 选 Very Doubt | **−10** |
| 任何句子 + 选 Not Sure | **0** |

**为什么这样设计**：

- **对称** = 同一档位选对得分与选错扣分**数值相同**，只有符号不同。所以分值衡量的是「你押了多大」，符号衡量「押没押对」。
- 五档分值本身**在信任轴上是非对称的**（质疑侧最大 10，信任侧最大 20）——这正是「质疑低风险、信任高风险」的体现，也是它比拖动条更像一个赌注的地方。
- `Not Sure` 永远 0：**唯一不会输的选项**。这是它作为一个真实选择的前提——如果保本还得分，那它就不是选择了。

> ⚠️ 这套计分是**先按对称实现**的（用户明确说「先做对称给分」），后续若要改成非对称（例如选错扣双倍）只需改 `scoring.ts` 的 `scoreFor()` 一个函数。

## 为什么是五个按钮而不是拖动条

拖动条把「我有多信」变成一个没人能负责的精细数字，而且大屏上没法同时读出上百个人的滑块位置。五个按钮是同一个决定，但**可以被喊出来**、可以在大屏上聚合。

## 为什么是「一道幻觉 + 一道站得住」

一个全是陷阱的回合教出来的是「什么都别信」，这本身是另一种失败模式。第二道题专门惩罚这种条件反射——它给出的是一段**自我限定、承认不确定性**的回答，那才是可信的样子。

所以两道题必须**保持一问一答的平衡**，不要都换成陷阱题。

## 倒计时：跟随引擎的暂停

每道题 **30 秒**，两道题共 60 秒。

**倒计时必须随引擎暂停而冻结。** 曾经用裸 `Date.now()` 实现，结果操作员按了暂停、节点头部时钟停了，但游戏内的倒计时**继续走**，题会在暂停期间被烧掉。这是实测抓到的 bug。

修法不是自己维护第二个时钟，而是**从引擎的状态推导**（`useNodeElapsed`）：

```ts
remainingMs = endsAt !== null ? max(0, endsAt - now) : heldMs
elapsed     = durationMs - remainingMs
```

`endsAt`（playing 时有值）和 `heldMs`（paused 时的冻结值）本来就已经是暂停感知的，所以相减就白拿了「已用时间」，**没有 ref、没有第二个时钟要同步**。playing 时 `now` 增长 → elapsed 增长；paused 时 `heldMs` 恒定 → elapsed 冻结。

实测的完整周期：

| 步骤 | 倒计时 | 结果 |
|---|---|---|
| 暂停中开始 | 30s | — |
| 暂停 +3s | 30s | 冻结 ✓ |
| 恢复 +4s | 27s | 正常走 ✓ |
| 再暂停 +4s | 26s → 26s | 停在 26s ✓ |
| 再恢复 +3s | 24s | **从 26s 续上**，没有跳变 ✓ |

> ⚠️ 一开始我用 `useRef` 累积暂停时长，被 oxlint 的 `react(refs)` 抓出来——渲染期读 ref 在并发渲染下不安全。改成从 store 推导后，两条 lint 都干净了，而且**少了一个需要同步的状态**。

## 当前状态与限制

- **题目硬编码在前端**（`content.ts`），3 道：假判例 → 诚实的不确定答案 → 假监管通函（两个陷阱一个正道，中间那道专门惩罚「一律怀疑」的反射）。题库上线后这里变成测试用的 fixture。
- **纯前端**：答案不落库、不上报，分数只存在于当前页面内存。刷新即清零（靠节点切换重新挂载来重置）。
- **揭晓是每题即时**的。要做成「全场一起揭晓」需要先有答案上报与聚合链路（`scores` 表目前仍是零读写）。
- **超时 = 未作答 = 0 分**，并直接进入揭晓（显示 `Time's up`）。这样一块没人操作的屏幕不会让整场演出停摆。

> ⚠️ **节点时长必须 ≥ 题目总时长**，否则引擎会在玩家答完前切走节点。当前 3 × 30s = 90s，节点 **96s**。改题目数量或 `QUESTION_SECONDS` 时**必须同步改 `flow.py` 的 `duration_sec`**；「节点时长够不够」有测试把关（`tests/test_flow.py::test_question_nodes_outlast_their_questions`），但题数与节点声明仍是两处手写。
