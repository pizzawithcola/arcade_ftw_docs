# Hallucination

主流程第 2 个节点（`type: game`，`game: hallucination`）。
代码：`arcade_ftw_fe/src/games/hallucination/`。

## 玩法

一次显示一条 **AI 的回复**，观众判断这句可不可信，从五档里选一个：

| 档位 | 分值 |
|---|---|
| Very Doubt | −10 |
| Doubt | −5 |
| Not Sure | 0 |
| Partial Trust | +10 |
| Full Trust | +20 |

题目内容是「用户问了什么」＋「AI 答了什么」，玩家只对**回复**做判断。

## 计分：对称，符号由对错决定

每题有一个**真值**：这句 `trust`（站得住）还是 `doubt`（幻觉）。

```ts
score = 档位分值 × (真值 === trust ? 1 : -1)
```

上表的分值是**真值为 trust 时**的得分；真值是 `doubt` 时整体取反。所以：

| 情况 | 得分 |
|---|---|
| 句子是真的 + 选 Full Trust | **+20** |
| 句子是幻觉 + 选 Full Trust | **−20** |
| 句子是幻觉 + 选 Very Doubt | **+10** |
| 句子是真的 + 选 Very Doubt | **−10** |
| 任何句子 + 选 Not Sure | **0** |

**为什么这样设计**：

- **对称** = 同一档位选对得分与选错扣分**数值相同**，只有符号不同。所以分值衡量的是「你押了多大」，符号衡量「押没押对」。
- 五档分值本身**在信任轴上是非对称的**（质疑侧最大 10，信任侧最大 20）——这正是「质疑低风险、信任高风险」的体现，也是它比拖动条更像一个赌注的地方。
- `Not Sure` 永远 0：**唯一不会输的选项**。这是它作为一个真实选择的前提——如果保本还得分，那它就不是选择了。

> ⚠️ 这套计分是**先按对称实现**的（用户明确说「先做对称给分」），后续若要改成非对称（例如选错扣双倍）只需改 `scoring.ts` 的 `scoreFor()` 一个函数。

## 为什么是五个按钮而不是拖动条

拖动条把「我有多信」变成一个没人能负责的精细数字，而且大屏上没法同时读出上百个人的滑块位置。五个按钮是同一个决定，但**可以被喊出来**、可以在大屏上聚合。

## 为什么是「两道幻觉 + 一道站得住」

一个全是陷阱的回合教出来的是「什么都别信」，这本身是另一种失败模式。中间那道题专门惩罚这种条件反射——它给出的是一段**自我限定、承认不确定性**的回答，那才是可信的样子。

## 当前状态与限制

- **题目硬编码在前端**（`content.ts`），只有 3 道。题库上线后这里变成测试用的 fixture。
- **纯前端**：答案不落库、不上报，分数只存在于当前页面内存。刷新即清零（`HallucinationGame` 靠节点切换重新挂载来重置）。
- **揭晓是每题即时**的。要做成「全场一起揭晓」需要先有答案上报与聚合链路（`scores` 表目前仍是零读写）。
- 节点时长仍是占位值（30 秒），而 3 道题的实际节奏由玩家自己点 Next 决定——**引擎的时长和玩家的节奏目前是脱钩的**。
